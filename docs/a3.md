# A3：过程内指针分析

## 作业要求

本次作业希望你实现一个 Java 上的过程内指向分析工具，计算 `main` 函数中引用变量可能指向的对象。分析主体将采用 Andersen 指向分析算法，使用流非敏感、域敏感的规则。

测试数据将采用指针分析的标注方式。标注语句分为两类：
- `Benchmark.alloc(id)`：表示下一条分配语句被标注输出编号；
- `Benchmark.test(id, x)`：表示需要输出 `x` 的指向集合对应被标注的编号。

测试保证 `Benchmark.alloc(id)` 的下一条语句一定是包含 `new` 的赋值语句。具体信息可以参考完整例子。

## 分析算法

见《过程内指针分析》课件的 Andersen 指向分析算法、域敏感分析和数组部分。

### 抽象地址与包含约束

设 $H$ 为分配语句产生的有限抽象地址集合，$P(p)\subseteq H$ 表示位置 $p$ 的指向集合，$h_s$ 是分配位置 $s$ 对应的抽象地址。你需要从 IR 中建立下列包含约束：

| 操作 | 包含约束 |
| --- | --- |
| `x = new T()` | $\{h_s\}\subseteq P(x)$ |
| `x = y` | $P(y)\subseteq P(x)$ |
| `x.f = y` | $\forall h\in P(x),\ P(y)\subseteq P(h,f)$ |
| `x = y.f` | $\forall h\in P(y),\ P(h,f)\subseteq P(x)$ |
| `C.f = y` | $P(y)\subseteq P(C.f)$ |
| `x = C.f` | $P(C.f)\subseteq P(x)$ |
| `a[i] = y` | $\forall h\in P(a),\ P(y)\subseteq P(h,*)$ |
| `x = a[i]` | $\forall h\in P(a),\ P(h,*)\subseteq P(x)$ |

针对数组，本次作业采用**数组粉碎**策略：同一个数组的所有下标共用一个元素汇总位置，不同分配位置的数组仍然区分。测试保证使用数组粉碎策略可以得到正确的分析结果。

在 Tai-e 中，你需要额外关注 `Stmt` 类型中的 `New`、`Copy`、`LoadField`、`StoreField`、`LoadArray` 和 `StoreArray` 子类。这些子类覆盖了上述所有操作。具体关系如 Tai-e 文档中所示：

![Tai-e lab](https://tai-e.pascal-lab.net/pa5/definitionstmt-subclasses.png)

同时为了区分 `x.f = y` 和 `C.f = y`（前者表示实例域变量，而后者表示静态字段），你可以使用 `LoadField` 类型的 `getFieldAccess()` 方法，判断其是否为 `InstanceFieldAccess` 子类来判断是否为静态字段。

本次作业不涉及静态或实例方法调用，且保证所有类均使用空构造。

## 完整例子

[AliasOverlap.java](../handout/tests/a3/AliasOverlap.java)

```java
package a3;
import benchmark.internal.Benchmark;
import benchmark.objects.A;
import benchmark.objects.B;

public class AliasOverlap {
    public static void main(String[] args) {
        Benchmark.alloc(1);
        B x = new B();
        Benchmark.alloc(2);
        B z = new B();
        Benchmark.alloc(3);
        A a = new A();
        Benchmark.alloc(4);
        A b = new A();
        Benchmark.alloc(5);
        A c = new A();
        B y = x;
        if (args.length > 0) {
            y = z;
        }
        x.p = a;
        z.p = b;
        y.p = c;
        Benchmark.test(1, x);
        Benchmark.test(2, z);
        Benchmark.test(3, y);
        Benchmark.test(4, x.p);
        Benchmark.test(5, z.p);
        Benchmark.test(6, y.p);
    }
}
```

该测试点将引用 `benchmark/objects/` 下的 `A` 和 `B` 类，这两个类的定义如下：

```java
// A.java
package benchmark.objects;

public class A {
    public A() {
    }
}

// B.java
package benchmark.objects;

public class B {
    public A p;
    public A q;

    public B() {
    }
}
```

对应 .out：

```text
1: 1
2: 2
3: 1 2
4: 3 5
5: 4 5
6: (3) (4) 5
```

`Benchmark.alloc(1);` 为 `x` 对应 `new` 操作标注 1，所以 `x` 此时指向地址 1。同理 `z` 指向地址 2。
由于 `y` 可能赋值为 `x` 或 `z`，所以其指向地址 1 或 2。故 `y.p = c` 将同时向这两个对象的 `p` 域加入地址 5。因此第四个查询输出 3 和 5，第五个查询输出 4 和 5。
第六个查询按上述包含约束将得到三个地址的并集，但具体执行中，`y.p = c` 已将所选对象的域写为地址 5，因此查询结果一定为 5。此处答案文件用括号表示可选的不精确输出：只要包含 5，无论是否输出 3 和 4 都视为正确。

注意 `x.q`, `y.q`, `z.q` 至始至终都没有被赋值，其实际值为 `null`，但 `null` 不会有任何标注，数据也保证不会对可能值为 `null` 的变量做询问，所以你不需要处理这类情况。

## 测试数据保证

所有操作均位于 `public static void main(String[] args)` 中，不涉及静态或实例方法调用且保证所有类均使用空构造。所有查询在具体执行中均指向带标号的对象或数组，不涉及 `null` 的赋值、比较或查询。本次作业没有隐藏测试。
