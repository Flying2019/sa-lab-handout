# A4：上下文敏感指针分析

## 作业要求

本次作业希望你在 A3 的基础上，实现过程间的 Andersen 指向分析，过程中需要使用类层次分析确定实例调用的目标方法。分析采用流非敏感、精确域敏感的规则，并用方法克隆策略处理上下文敏感性。

## 分析算法

见《过程内指针分析》课件的 Andersen 指向分析算法和域敏感分析部分，以及《过程间指针分析》课件的类层次分析和“降低上下文敏感性”部分。

### 类层次分析

类层次分析（Class Hierarchy Analysis，CHA）需要根据接收变量的声明类型，确定方法调用可能的目标。

例如，变量 `i` 的声明类型是接口 `I`，`A` 和 `B` 都实现了 `I`，则 `i.m()` 的可能目标包括 `A.m()` 和 `B.m()`。类似的，对类类型的接收变量，也需要考虑该类及其所有非抽象子类。

在本次作业中，你只需要进行最基础的类层次分析。例如若变量 `i` 的声明类型为 `I`，对调用 `i.m()` 按下列规则查找目标：

1. 若 `I` 是类，枚举它自身及其子类中的非抽象类；若 `I` 是接口，枚举直接或间接实现该接口的非抽象类。
2. 对每个候选类，按完整方法签名查找 `m` 的实现。若该类中实现了该方法则直接加入集合，否则沿父类依次向上查找直到第一个实现。

数据保证仅进行该类层次分析就可以得到期望结果。

### 基于克隆的上下文敏感分析

本次作业将使用精确域敏感的策略，并使用克隆策略处理上下文。

设 $h_s$ 为分配位置 $s$ 对应的抽象地址，$P(c,m\|x)$ 为上下文 $c$ 中方法 $m$ 的局部变量 $x$ 的指向集合，$P(h,d)$ 为对象 $h$ 的域 $d$ 的指向集合。当上下文为 $c$ 时，对域读写建立下列约束：

$$
\begin{aligned}
x.d=y&:\quad\forall h\in P(c,m\|x),\ P(h,d)\supseteq P(c,m\|y)\\
x=y.d&:\quad\forall h\in P(c,m\|y),\ P(c,m\|x)\supseteq P(h,d)
\end{aligned}
$$

本次作业按最近两次调用位置克隆方法。例如当前的上下文是 $(\ell_2,\ell_1)$，其中 $\ell_1$ 是上次调用位置，$\ell_2$ 是上上次调用位置。现在在 $\ell$ 位置调用了新方法，则被调用者的上下文为：

$$
c'=(\ell_1,\ell)
$$

不足两次的调用历史用 $\bot$ 补齐。

特别的，如果一个变量属于静态域，则其指向集合全局共享，可以视作在同一个全局上下文中。针对数组，本次作业同样采用**数组粉碎**策略，详见 [a3 文档](a3.md)。

实际实现时，你可以为每个“方法、局部变量”组合添加上下文前缀以区分不同上下文的变量，并在这些变量之间建立约束。

### 参数与返回值传递

除了函数内部的局部变量，你还需要对参数和返回值做特殊处理。

对在方法 $f$ 中的实例调用 `x = y.g(a)` 进行分析，首先需要用类层次分析确定可能的目标方法。对每个目标 $m$，按上述规则选取被调上下文 $c'$。然后设 $p$ 是实参 $a$ 对应的形参，添加约束：

$$
\begin{aligned}
P(c',m\|\mathrm{this})&\supseteq P(c,f\|y)\\
P(c',m\|p)&\supseteq P(c,f\|a)\\
P(c',m\|\mathrm{ret})&\supseteq\bigcup_{r\in\mathrm{Returns}(m)}P(c',m\|r)\\
P(c,f\|x)&\supseteq P(c',m\|\mathrm{ret})
\end{aligned}
$$

其中 $\mathrm{Returns}(m)$ 为 $m$ 内部所有返回语句返回的引用变量集合。多个实参与形参按位置分别传递。静态调用不建立 `this` 的约束，没有引用返回值的调用不建立返回值约束。

### Tai-e 接口

`JClass` 是 Tai-e 表示 Java Class 的类型，你需要重点关注该类型。

在进行类层次分析时，你可以通过 `World.get().getClassHierarchy().applicationClasses()` 获取所有的类信息，该方法会返回一系列 `JClass`。然后你可以通过 `JClass.getSuperClass()`、`JClass.getInterfaces()` 获取一个类的父类和接口。

在分析实例调用时，你可以通过 `Invoke.getMethodRef().getSubsignature()` 取得方法签名，再用 `JClass.getDeclaredMethod(signature)` 查找指定类中声明的方法；没有声明时沿父类继续查找。通过 `JMethod.getIR()` 获取目标方法的 IR。

特别的，实例方法的 `IR.getParams()` 不会包含 `this`。你可以额外调用 `IR.getThis()` 来获取 `this` 变量的信息。

## 完整例子

```java
package a4;
import benchmark.internal.Benchmark;
import benchmark.objects.A;
import benchmark.objects.J;
import benchmark.objects.K;

public class Inheritance {
    static A call(J x, A a) {
        return x.f(a);
    }

    public static void main(String[] args) {
        Benchmark.alloc(1);
        A a = new A();
        Benchmark.alloc(2);
        J.p = new A();
        Benchmark.alloc(3);
        J x = new K();
        A b = call(x, a);
        Benchmark.test(1, b);
        Benchmark.test(2, x);
    }
}
```

该程序使用 `benchmark/objects/` 下的 [A](../handout/benchmark/objects/A.java)、[I](../handout/benchmark/objects/I.java)、[J](../handout/benchmark/objects/J.java) 和 [K](../handout/benchmark/objects/K.java)，相关类和接口的定义如下：

```java
// A.java
package benchmark.objects;

public class A {
    public A() {
    }
}

// I.java
package benchmark.objects;

public interface I {
    A f(A a);
}

// J.java
package benchmark.objects;

public class J implements I {
    public static A p;
    public static A q;

    public J() {
    }

    public A f(A a) {
        return a;
    }
}

// K.java
package benchmark.objects;

public class K extends J {
    public K() {
    }

    public A f(A a) {
        return J.p;
    }
}
```

对应 .out：

```text
1: (1) 2
2: 3
```

其中 `K` 继承 `J`。所以当 `call` 方法内调用参数 `x` 的方法 `x.f(a)` 时，需要使用类层次分析收集 `f` 的实现。分析得到 `b` 的指向集合为地址 1 和 2。

如果结合指向结果进一步确定调用目标，会得知 `x` 只可能是 `K` 类型，所以 `b` 一定指向 `J.p`，精确分析结果返回 2。但这里同时返回 1 也视为正确。
